Lab 7 - Web Server Log

Student Maxwell King Environment Kali / Metasploitable3 (VirtualBox)

This lab was reading through a raw web server access log to answer questions about what happened on the server over about six days.

What is the date/time range of the log?

The log starts on April 19, 2010 at 6:36 AM and ends on April 24, 2010 at 6:51 PM. That is about 6 days worth of web server activity, all in the -0700 timezone.

Were any proxies involved? If so, which ones?

Yes. Looking through the log I could see requests going out to proxyjudge1.proxyfire.net and www.wantsfly.com, both of which are known proxy-related services. There were also CONNECT requests from IPs in the 193.109.122.x range using a tool called pxyscand/2.1, which was being used to scan for open proxies on the server.

Which pages were clients accessing with GET requests?

The pages being accessed with GET requests were /, /feed/, /login/, /signup/, /robots.txt, /wp-admin, and /wp-admin/. Most of the traffic was to /feed/ from what looked like automated feed readers.

What version of WordPress is being used?

WordPress 2.9.2. You can see it in the user-agent string on the wp-cron requests, which shows WordPress/2.9.2 and the site URL.

Which page(s) is HTTP POST going to?

POST requests were going to /wp-cron.php?doing_wp_cron and /signup/. The wp-cron ones are just WordPress running background tasks automatically. The /signup/ POST requests came from the same IP over and over, which looks like someone trying to create a bunch of accounts.

What proxy scanner was being used?

The proxy scanner being used was pxyscand/2.1. It showed up in CONNECT requests trying to reach 72.51.18.254 on port 6677, coming from multiple IPs in the 193.109.122.x range.

A password was set. What was the ID and password set?

The ID was DoomsDay and the password was youcanrap. On April 20 at 7:48 AM, an IP address made a GET request to edit.yahoo.com with the login and password passed directly in the URL. The credentials were sitting in plain text in the log, which is a good example of why you should never pass sensitive information through a GET request.

What is the name of the bot that accessed the system, and what IP address did it come from?

The bot was NaverBot/1.0 and it came from IP 114.111.36.26. NaverBot is a web crawler from the South Korean search engine Naver. It showed up twice in the log, hitting /robots.txt and the homepage to index the site.
