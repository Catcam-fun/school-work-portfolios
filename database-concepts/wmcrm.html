Wallingford Motors CRM

Student Maxwell King Course COP 2937 Term Summer 2026

This is a database I built up week by week in Database Concepts, working through a car dealership system called Wallingford Motors. Each assignment picked up the previous week's file and added to it: a new table, a new query, a form or a report. By the end it tracks customers, their contact history, salespeople, and vehicle inventory. Each section below is one submission, and each links the Access file exactly as it was turned in that week.

Week 1: Getting Started with Microsoft Access

Submitted May 24

The first version was a single Customer table with everything in it, including a Phone and a Fax field. On top of that table I built the WMCRM Customer Data Form for entering and editing customers one at a time, and the Wallingford Motors Customer Report for a printable customer list.

TableFields
CustomerCustomerID, LastName, FirstName, Address, City, State, ZIP, Phone, Fax, EmailAddress

Week 2: The Relational Model

Submitted May 27

Week 2 applied the relational model to that single table. A customer can have more than one phone number, so Phone and Fax came out of Customer and moved into their own Phone_Number table with a PhoneType column. A new Contact table logs every call, email, and meeting with a customer. Both tables link back to Customer through CustomerID in one-to-many relationships, and the form and report were updated to match.

Week 3: Structured Query Language (SQL) Basics

Submitted June 3

Week 3 was the first SQL. The queries start with a plain SELECT *, then move to filtering and sorting, a join, and a parameter query. They were built in both SQL view and Access's query designer (QBE).

Filtering and Sorting

Pull customers past a certain ID, sorted by last name in reverse order.

SELECT
    Customer.CustomerID,
    Customer.LastName,
    Customer.FirstName
FROM
    Customer
WHERE
    (((Customer.CustomerID) > 2))
ORDER BY
    Customer.LastName DESC;

Customer Contact History

Join Customer to Contact to pull the full contact history (date, type, and remarks) for one specific customer, ordered chronologically.

SELECT
    Customer.LastName,
    Customer.FirstName,
    Contact.ContactDate,
    Contact.ContactType,
    Contact.Remarks
FROM
    Customer
    INNER JOIN Contact ON Customer.CustomerID = Contact.CustomerID
WHERE
    (((Customer.CustomerID) = 2))
ORDER BY
    Contact.ContactDate;

Customer Contact History, Parameterized

Same report, but turned into a parameter query. Instead of hardcoding a customer's ID into the SQL, it prompts for one at runtime, so the same query works for any customer without editing the SQL each time.

SELECT
    Customer.LastName,
    Customer.FirstName,
    Contact.ContactDate,
    Contact.ContactType,
    Contact.Remarks
FROM
    Customer
    INNER JOIN Contact ON Customer.CustomerID = Contact.CustomerID
WHERE
    (((Customer.CustomerID) = [Enter the CustomerID Number:]))
ORDER BY
    Contact.ContactDate;

Creating the SALESPERSON Table

The last query of the week used SQL DDL rather than the table designer to create a SALESPERSON table. Each salesperson is identified by a nickname, which is the primary key.

CREATE TABLE SALESPERSON(
  NickName       Char(35)     NOT NULL,
  LastName       Char(25)     NOT NULL,
  FirstName      Char(25)     NOT NULL,
  HireDate       Date         NOT NULL,
  WageRate       Numeric      NOT NULL,
  CommissionRate Numeric      NOT NULL,
  OfficePhone    Char(12)     NOT NULL,
  EmailAddress   Varchar(100) NOT NULL,
  CONSTRAINT     SALESPERSON_PK PRIMARY KEY(NickName)
);

I then added a NickName column to Customer as a foreign key and related the two tables, so every customer is assigned to one salesperson.

Week 4: Data Modeling Basics

Submitted June 14

With salespeople linked to customers, Week 4 pulled three tables together. This query joins each salesperson to their customers and each customer to their contact history:

SELECT
    SALESPERSON.NickName,
    SALESPERSON.LastName AS SALESPERSON_LastName,
    SALESPERSON.FirstName AS SALESPERSON_FirstName,
    SALESPERSON.OfficePhone,
    SALESPERSON.EmailAddress AS SALESPERSON_EmailAddress,
    Customer.LastName AS Customer_LastName,
    Customer.FirstName AS Customer_FirstName,
    Customer.EmailAddress AS Customer_EmailAddress,
    Contact.ContactDate,
    Contact.ContactType,
    Contact.Remarks,
    Customer.CustomerID
FROM
    (SALESPERSON
    INNER JOIN Customer ON SALESPERSON.NickName = Customer.NickName)
    INNER JOIN Contact ON Customer.CustomerID = Contact.CustomerID;

It drives the WMCRM Salesperson Contacts Report, which groups every customer contact under the salesperson responsible for it. The WMCRM Salesperson Contacts Form shows the same data on screen as a main form with two linked subforms: pick a salesperson, see their customers in the Customer Data subform, and the Contact Data subform follows whichever customer is selected.

Week 7: Database Design Basics

Submitted June 27

The last addition was vehicle inventory. A new VEHICLE table tracks each car by InventoryID, model (HiStandard, HiLuxury, SUHi), and VIN. SALESPERSON gained an InventoryID foreign key, and a relationship between the two tables ties each salesperson to a vehicle.

TableFields
VEHICLEInventoryID, Model, VIN
SALESPERSONNickName, LastName, FirstName, HireDate, WageRate, CommissionRate, OfficePhone, EmailAddress, InventoryID

That leaves the final schema at five tables: Customer, Contact, Phone_Number, SALESPERSON, and VEHICLE.
