Database Concepts

Wallingford Motors CRM

Student Maxwell King Course COP 2937 Term Spring 2026

This is a database I built up week by week in Database Concepts, working through a car dealership system called Wallingford Motors. Each week added something: a new table, a new query, a form or a report, working toward a system that tracks customers, their contact history, salespeople, and vehicle inventory. It's more a running record of the semester than one finished project, so this page walks through it in the order the pieces were added.

Starting Tables: Customers and Contacts

The first version held three tables. Customer stores who the customer is, Contact logs every phone call, email, and meeting with that customer, and Phone_Number lets one customer have several numbers on file (home, cell, fax) instead of cramming them into a single field.

Queries

The first set of queries was built in Access's query designer (QBE) and moves from basic filtering to joined, parameterized reports.

Filtering and Sorting

Pull customers past a certain ID, sorted by last name in reverse order.

SELECT
    Customer.CustomerID,
    Customer.LastName,
    Customer.FirstName
FROM
    Customer
WHERE
    (((Customer.CustomerID) > 2))
ORDER BY
    Customer.LastName DESC;

Customer Contact History

Join Customer to Contact to pull the full contact history (date, type, and remarks) for one specific customer, ordered chronologically.

SELECT
    Customer.LastName,
    Customer.FirstName,
    Contact.ContactDate,
    Contact.ContactType,
    Contact.Remarks
FROM
    Customer
    INNER JOIN Contact ON Customer.CustomerID = Contact.CustomerID
WHERE
    (((Customer.CustomerID) = 2))
ORDER BY
    Contact.ContactDate;

Customer Contact History, Parameterized

Same report, but turned into a parameter query. Instead of hardcoding a customer's ID into the SQL, it prompts for one at runtime, so the same query works for any customer without editing the SQL each time.

SELECT
    Customer.LastName,
    Customer.FirstName,
    Contact.ContactDate,
    Contact.ContactType,
    Contact.Remarks
FROM
    Customer
    INNER JOIN Contact ON Customer.CustomerID = Contact.CustomerID
WHERE
    (((Customer.CustomerID) = [Enter the CustomerID Number:]))
ORDER BY
    Contact.ContactDate;

Customer Data Form and Report

Next came the front end. The WMCRM Customer Data Form gives a salesperson a single screen to look up and edit a customer's record without opening the raw table, and the Wallingford Motors Customer Report formats the customer list for printing.

Adding Salespeople with SQL

The SALESPERSON table was created with a SQL CREATE TABLE statement instead of the table designer. Each salesperson is identified by a nickname, which became the primary key.

CREATE TABLE SALESPERSON(
  NickName       Char(35)     NOT NULL,
  LastName       Char(25)     NOT NULL,
  FirstName      Char(25)     NOT NULL,
  HireDate       Date         NOT NULL,
  WageRate       Numeric      NOT NULL,
  CommissionRate Numeric      NOT NULL,
  OfficePhone    Char(12)     NOT NULL,
  EmailAddress   Varchar(100) NOT NULL,
  CONSTRAINT     SALESPERSON_PK PRIMARY KEY(NickName)
);

A NickName column was then added to Customer so every customer is assigned to a salesperson.

Vehicle Inventory

The last table, VEHICLE, tracks inventory by InventoryID, model (HiStandard, HiLuxury, SUHi), and VIN. Salespeople point to a vehicle through an InventoryID column.

Salesperson Contacts Form and Report

With salespeople linked to customers, the final pieces pull all three tables together. This query joins each salesperson to their customers and each customer to their contact history:

SELECT
    SALESPERSON.NickName,
    SALESPERSON.LastName AS SALESPERSON_LastName,
    SALESPERSON.FirstName AS SALESPERSON_FirstName,
    SALESPERSON.OfficePhone,
    SALESPERSON.EmailAddress AS SALESPERSON_EmailAddress,
    Customer.LastName AS Customer_LastName,
    Customer.FirstName AS Customer_FirstName,
    Customer.EmailAddress AS Customer_EmailAddress,
    Contact.ContactDate,
    Contact.ContactType,
    Contact.Remarks,
    Customer.CustomerID
FROM
    (SALESPERSON
    INNER JOIN Customer ON SALESPERSON.NickName = Customer.NickName)
    INNER JOIN Contact ON Customer.CustomerID = Contact.CustomerID;

It drives the WMCRM Salesperson Contacts Report, which groups every customer contact under the salesperson responsible for it. The WMCRM Salesperson Contacts Form shows the same data as a main form with two linked subforms: pick a salesperson, see their customers in the Customer Data subform, and the Contact Data subform follows whichever customer is selected.
